# saved-by-the-ical

School bell schedules and calendars as separate iCal subscriptions. Each
calendar only has events on actual school days: holidays, breaks and summer
are left out automatically.

**📱 [Today's schedules](https://aaronj84.github.io/saved-by-the-ical/)**: who's in
class right now and when they're next free. On iPhone: Share → Add to Home Screen.
Its "Subscribe to calendars" section has one-tap subscribe links.

## Subscribe

Copy a link below, then:

- **iPhone / iPad:** Settings → Apps → Calendar → Calendar Accounts → Add Account → Other → Add Subscribed Calendar
- **Mac:** Calendar → File → New Calendar Subscription
- **iCloud sharing:** subscribe on a Mac with *Location: iCloud* so it syncs to every device

## Updating the calendars

All data lives in `data/` as YAML. Edit it, push to `main`, and the
[Build feeds](.github/workflows/build-feeds.yml) action regenerates the
`.ics` files and the links above. Calendar apps pick up changes on their next
refresh (Apple: usually within hours; Google: up to a day).

| file | what's in it |
|------|--------------|
| `data/districts/canyons-2026-27.yaml` | first/last day, semesters, every day off and the A/B rotation — shared by all Canyons schools except where a school overrides (Brighton: trimesters, own days) |
| `data/schools/<school>.yaml` | that school's bell schedules, weekly pattern, A/B rotation and feeds |

A snow day or schedule change goes in the district file (`days:`), once, and
flows into every school's calendar:

```yaml
- { date: 2027-01-12, no_school: true, title: Snow Day }
- { date: 2027-03-03, schedule: friday, title: Early Out }   # school file
```

Each date resolves in this order (later wins): weekly pattern → A/B rotation
schedule → `days:` overrides in file order (district first, then school). The
A/B rotation advances once per school day and skips days off; an override can
force a label (`rotation: A`) or hold it (`advance_rotation: false`).

Feed components (`include:`): `bells` (timed periods), `day_labels` ("A Day"
all-day markers), `days` (titled holidays/changes), `events`. Filters:
`rotation: [A]` (only A days), `periods: ["1", "2"]` (only those periods),
`when:` (day rules combining rotation with a date range or named `terms:`
entry, e.g. `{ rotation: [B], term: semester_1 }`), `group:` (lunch group for
schedules whose periods vary by group), `include_breaks`, `no_school_only`,
`categories`. See
`examples/example-high.yaml` for every option, including per-student feeds
that relabel periods with class names.

Event IDs are stable, so edits update events in place instead of duplicating
them. Don't rename a school or feed `id` once people are subscribed: that
changes the URL.

## Development

```sh
pip install -e '.[dev]'
sbtical check data/schools/*.yaml data/people/*.yaml data/carpool.yaml          # validate + school-day counts
sbtical day data/schools/jordan.yaml 2026-12-18   # how one date resolves
sbtical build data/schools/*.yaml data/people/*.yaml data/carpool.yaml          # write feeds/
sbtical readme data/schools/*.yaml data/people/*.yaml data/carpool.yaml         # refresh the links above
sbtical site data/schools/*.yaml data/people/*.yaml data/carpool.yaml           # build the Pages site into _site/
(cd _site && python3 -m http.server)   # preview; add ?now=2026-11-16T10:05 to test a time
pytest
```
